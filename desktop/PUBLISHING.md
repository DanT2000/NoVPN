# NoVPN Desktop — публикация, версии, что отдаёт сайт

Эта папка (`desktop/`) — единственный источник, из которого материалы уезжают
и в GitHub, и на сайт `vpn.appswire.ru`. Здесь описано, что где лежит, как
хранить версии и что именно должен отдавать сайт.

---

## 1. Что лежит в папке

```
desktop/
├─ latest.json          # манифест обновления: какая версия сейчас актуальна
├─ vpn.exe              # текущий установщик (та версия, что в latest.json)
├─ README.md            # описание проекта
├─ PUBLISHING.md        # этот файл
└─ guide/               # инструкция для пользователей
   ├─ novpn-desktop-guide.md
   └─ images/           # 14 скриншотов, пути в .md относительные (images/…)
```

### `latest.json` — сердце обновлений

Приложение само проверяет обновления по этому файлу. Пример:

```json
{
  "product": "NoVPN Desktop",
  "version": "0.2.2",
  "channel": "stable",
  "url": "https://raw.githubusercontent.com/DanT2000/NoVPN/main/desktop/vpn.exe",
  "sha256": "948f6690c2cd…",
  "signature": "v7b6+eFr7D50…",
  "sizeBytes": 16104779,
  "notes": "Что нового в этой версии"
}
```

- `version` — номер новой версии. Приложение сравнивает его со своей.
- `url` — откуда скачать установщик.
- `sha256` + `signature` — контроль целостности и **подпись Ed25519**. Без
  верной подписи приложение обновление **отклонит**. Подпись ставит только
  разработчик своим приватным ключом (в репозиторий он не попадает).

> **Важно:** менять `latest.json` вручную нельзя — `sha256` и `signature`
> должны быть пересчитаны под конкретный `vpn.exe`. Их генерирует скрипт
> публикации при сборке новой версии.

### Куда приложение ходит за обновлением

Проверяются два адреса **по порядку**, берётся первый рабочий:

1. `https://vpn.appswire.ru/desktop/latest.json`  ← **основной (сайт)**
2. `https://raw.githubusercontent.com/DanT2000/NoVPN/main/desktop/latest.json`  ← резерв (GitHub)

Сайт стоит первым специально: raw.github в РФ часто недоступен, а обновляться
нужно и без включённого VPN.

---

## 2. Как хранить версии — рекомендация

Установщик весит ~16 МБ. Если каждую версию класть в git как `vpn.exe`,
репозиторий будет расти на 16 МБ с каждым релизом навсегда (git хранит все
старые копии). Поэтому:

### Рекомендуемая схема

| Что | Где хранить | Зачем |
|-----|-------------|-------|
| **Актуальный манифест** `latest.json` | в этой папке (git + сайт) | крошечный, его читает приложение |
| **Установщики всех версий** | **GitHub Releases** (тег `v0.2.2`, файл-ассет `NoVPN-0.2.2-setup.exe`) | архив версий без раздувания репозитория, стабильные ссылки, откат возможен |
| **Инструкция** | `desktop/guide/` (git + сайт) | страница для пользователей |

При такой схеме `latest.json.url` указывает на ассет релиза, например:
`https://github.com/DanT2000/NoVPN/releases/download/v0.2.2/NoVPN-0.2.2-setup.exe`

Тогда тяжёлый `vpn.exe` в репозиторий вообще не коммитится.

### Как сейчас (проще, но с ростом репозитория)

Сейчас установщик лежит прямо в папке как `vpn.exe` (перезаписывается каждый
релиз), а `latest.json.url` смотрит на него в GitHub raw. Это работает, но
историю версий не хранит и раздувает git. Годится как временный вариант.

> **Вывод:** для долгой жизни — GitHub Releases для бинарников + `latest.json`
> в папке. Имя установщика на сайте лучше держать стабильным
> (`vpn.exe` или `NoVPN-setup.exe`), чтобы кнопка «Скачать» не менялась от версии
> к версии.

## 3. Что должен отдавать сайт `vpn.appswire.ru`

Это и есть задание для настройки сайта.

### 3.1. Манифест обновлений — **обязательно починить**

Сейчас `https://vpn.appswire.ru/desktop/latest.json` возвращает **HTML главной
страницы сайта**, а не JSON (SPA отдаёт `index.html` на неизвестный путь).
Из-за этого основной канал обновлений не работает, приложение спасает только
резерв на GitHub.

**Нужно:** отдавать по этому адресу именно файл `desktop/latest.json`
с заголовком `Content-Type: application/json`. То есть путь `/desktop/*` должен
раздаваться как статические файлы, а не уходить в SPA-фолбэк.

### 3.2. Установщик

По адресу из `latest.json.url` должен лежать рабочий `.exe`. Варианты:
- отдавать `desktop/vpn.exe` напрямую с сайта, **или**
- поставить в `url` ссылку на ассет GitHub Releases (см. раздел 2).

Плюс кнопка **«Скачать для Windows»** на сайте → на тот же установщик.

### 3.3. Инструкция

- Файл: `desktop/guide/novpn-desktop-guide.md`, картинки рядом в
  `desktop/guide/images/` (пути в тексте относительные — `images/…`).
- Отдавать как страницу, например `https://vpn.appswire.ru/desktop/guide/`
  (или любой адрес вроде `/instrukciya`) — важно лишь, чтобы **картинки
  подтягивались по относительным путям** рядом с отрендеренным Markdown.
- Оформление обычное для Markdown: заголовки, таблицы, картинки. Инлайн-HTML в
  тексте используется минимально — только `<p align="center">` для центровки
  скриншотов; если движок сайта вырезает HTML, картинки просто встанут по
  левому краю (всё остальное отрендерится штатно).

## 4. Порядок выпуска новой версии (памятка)

1. Собрать установщик новой версии (`cargo tauri build`).
2. Прогнать скрипт публикации: он подписывает `.exe` ключом Ed25519 и
   пересчитывает `latest.json` (version, sha256, signature, sizeBytes).
3. Разложить: `latest.json` — в эту папку; установщик — по выбранной схеме
   (GitHub Releases или `vpn.exe` в папке).
4. Залить в GitHub и на сайт. Проверить, что
   `https://vpn.appswire.ru/desktop/latest.json` отдаёт **JSON**, а не HTML.
5. В приложении: «Настройки → Обновления → Проверить» — должна появиться новая
   версия и обновиться в одно нажатие.
