# NoVPN Desktop — раздача и авто-обновление

Эта папка — **канал распространения** десктоп-приложения NoVPN (`vpn.exe`) через GitHub.
Сюда кладётся новая версия и «инструкция» (манифест), а приложение само проверяет
обновления и качает свежую сборку.

## Файлы

| Файл | Что это |
|------|---------|
| `latest.json` | Манифест текущей версии: номер, ссылка на файл, контрольная сумма, заметки. **Приложение читает его, чтобы понять, есть ли обновление.** |
| `vpn.exe` | Собственно приложение (сейчас — заглушка, замените реальной сборкой). |

## Стабильные публичные URL (их можно давать людям / зашивать в приложение)

- Манифест: `https://raw.githubusercontent.com/DanT2000/NoVPN/main/desktop/latest.json`
- Скачать приложение: `https://raw.githubusercontent.com/DanT2000/NoVPN/main/desktop/vpn.exe`

`raw.githubusercontent.com/.../main/...` всегда отдаёт то, что сейчас в ветке `main` —
то есть последнюю версию, которую вы закоммитили.

## Как выпустить новую версию

1. Соберите `vpn.exe`.
2. Положите его в эту папку (замените старый).
3. Обновите `latest.json`:
   - `version` — новый номер (например `1.2.0`);
   - `releasedAt` — дата;
   - `sha256` — контрольная сумма файла: PowerShell `Get-FileHash vpn.exe -Algorithm SHA256`;
   - `sizeBytes` — размер файла в байтах;
   - `notes` — что нового (текст для пользователя);
   - `mandatory` — `true`, если обновление обязательное.
4. Закоммитьте и запушьте в `main`. Всё — новая версия «опубликована».

## Как приложение обновляется (протокол)

1. Скачивает `latest.json` по стабильному URL выше.
2. Сравнивает `version` из манифеста со своей версией (semver).
3. Если в манифесте новее — скачивает файл по `url`, при наличии сверяет `sha256`,
   заменяет себя и перезапускается. `mandatory: true` = не давать работать на старой.

## Формат `latest.json`

```json
{
  "product": "NoVPN Desktop",
  "version": "1.2.0",
  "channel": "stable",
  "releasedAt": "2026-08-20",
  "mandatory": false,
  "minSupportedVersion": "1.0.0",
  "url": "https://raw.githubusercontent.com/DanT2000/NoVPN/main/desktop/vpn.exe",
  "sha256": "…",
  "sizeBytes": 12345678,
  "notes": "Что нового в этой версии."
}
```

## Важно про размер репозитория

`git` хранит **всю историю** файлов. Если `vpn.exe` весит десятки МБ и вы часто его
обновляете, репозиторий будет расти и уже не «похудеет». Два варианта:

- **Просто и быстро (как сейчас):** держать `vpn.exe` прямо здесь. Годится для нечастых
  релизов / небольшого бинарника.
- **Правильно для больших/частых сборок:** заливать `vpn.exe` как **GitHub Release asset**
  (вкладка Releases), а в `latest.json` ставить `url` на ссылку этого ассета. Тогда
  бинарники не попадают в историю `git`, а манифест (крошечный) остаётся здесь.

Можно начать с первого и перейти на второй, когда появятся реальные сборки.
