# NoVPN

**NoVPN** — панель управления VPN-доступами: выпуск и учёт клиентских конфигураций
(Xray / AmneziaWG), управление пользователями, серверами, устройствами, трафиком,
Telegram-ботом и клиентскими приложениями.

Проект состоит из центральной панели (control plane) и лёгких агентов, которые
работают на VPN-серверах и выполняют только разрешённые операции.

> ⚠️ Продукт в интерфейсе называется **NoVPN**. Репозиторий — `0VPN`.
> Старый репозиторий `ZeroVPN` используется только как источник кода и логики,
> разработка ведётся здесь.

## Архитектура

```
┌──────────────────────────────────────────────────────────────┐
│                         Браузер (SPA)                          │
│   apps/web — React + Vite + TypeScript, адаптивный, RU         │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS / JSON API
┌───────────────────────────▼──────────────────────────────────┐
│                    apps/manager (control plane)                │
│   Express + TypeScript. Пользователи, коды, устройства,        │
│   лимиты, трафик, серверы, задания, Telegram, audit log.       │
│   Отдаёт собранный фронтенд. Хранилище: SQLite (том).          │
└───────────────────────────┬──────────────────────────────────┘
                            │ исходящее защищённое соединение
                            │ (heartbeat + очередь заданий)
┌───────────────────────────▼──────────────────────────────────┐
│              apps/agent (NoVPN Agent, на VPN-сервере)          │
│   Аудит сервера, драйверы протоколов (Xray, AmneziaWG,         │
│   HTTP/SOCKS5), выпуск/отзыв доступов, сбор статистики.        │
└──────────────────────────────────────────────────────────────┘

packages/shared — общие типы, контракты API, перечисления статусов.
```

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт (локально)

Требуется **Node.js ≥ 20** и npm ≥ 10.

```bash
npm install
cp .env.example .env        # заполнить значения (см. комментарии в файле)
npm run dev                 # manager (API) + web (Vite) параллельно
```

- Веб-интерфейс (dev): http://localhost:5173
- API / панель (dev): http://localhost:3000

На этапе разработки фронтенд может работать без backend на mock-данных:
установите `VITE_USE_MOCK=true`. Весь доступ к данным идёт через единый
API-адаптер (`apps/web/src/api`), поэтому переключение mock ↔ реальный API
не требует переписывания компонентов.

Полное руководство: [docs/LOCAL_DEV.md](docs/LOCAL_DEV.md).

## Развёртывание

Две **независимые** установки одного кода через Coolify:

| Установка | Ветка | Сервер Coolify | Домен |
|-----------|-------|----------------|-------|
| Dev / отдельная | `develop` | `localhost` | https://vpn.dev.appswire.ru |
| Основная | `main` (release) | `apps` | https://vpn.appswire.ru |

Установки **не** делят между собой БД, тома, ключи шифрования, сессии,
Telegram-токены, ключи агентов, SSH-данные, пользователей и статистику.

Инструкция: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
Миграция и импорт старых конфигов: [docs/MIGRATION.md](docs/MIGRATION.md).

## Безопасность

- Секреты **никогда** не попадают в Git: пароли, токены, SSH-ключи, VPN-конфиги,
  дампы БД. См. `.gitignore` и `.env.example` (только имена переменных).
- Секреты в БД (Telegram-токены, proxy-пароли, ключи агентов) шифруются
  `ENCRYPTION_KEY`.
- Bot Token и proxy-пароли не возвращаются через API после сохранения.
- Продакшн разворачивается только из зафиксированного commit / release.
- Без force push и переписывания истории.
