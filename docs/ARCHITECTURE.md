# Архитектура NoVPN

## Обзор

NoVPN построен по модели **control plane + агенты**:

- **Панель (`apps/manager`)** — центр управления. Хранит пользователей, коды,
  устройства, серверы, задания, настройки, Telegram, audit log. Отдаёт JSON API
  и собранный фронтенд. Никогда не подключается к VPN-серверам напрямую для
  выполнения операций — только ставит задания.
- **Агент (`apps/agent`)** — работает на каждом VPN-сервере. Устанавливает
  **исходящее** защищённое соединение с панелью (работает за NAT), забирает
  задания, выполняет их идемпотентно, шлёт heartbeat и статистику.
- **Веб (`apps/web`)** — SPA. Пользовательская публичная часть (ввод кода,
  выпуск конфига) и админ-часть (полное управление). Работает одинаково на
  десктопе и телефоне.
- **`packages/shared`** — общие типы и контракты API.

```
web ──HTTP──> manager <──outbound WSS/HTTPS── agent ──> Xray / AmneziaWG / proxy
                 │
                 └── SQLite (том)
```

## Почему такой стек

- **Node + TypeScript** во всех трёх приложениях — единый язык, переиспользование
  типов из `packages/shared`, преемственность со старым стеком (Express + Node).
- **SQLite (better-sqlite3)** — совпадает со старой БД, упрощает миграцию и
  бэкапы (один файл на томе), достаточно для масштаба control plane. Слой доступа
  к данным изолирован — при росте заменяется на Postgres без переписывания логики.
- **React + Vite** — быстрый современный SPA, адаптивный, легко собирается в
  статику и отдаётся панелью одним контейнером.

## Разделение сигналов состояния сервера

Три **разных** состояния, которые нельзя смешивать (см. `AgentConnectivity`,
`ServiceHealth`, `EndpointReachability`):

| Сигнал | Что значит |
|--------|------------|
| **Agent connected** | Агент на связи с панелью |
| **VPN service healthy** | Служба (Xray/AmneziaWG) на сервере жива |
| **Public endpoint reachable** | Порт доступен снаружи (может быть закрыт NAT) |

Домашний сервер за NAT может иметь подключённый агент, но недоступный endpoint —
это разные проблемы, и интерфейс показывает их отдельно.

## Драйверы протоколов

Каждый протокол — отдельный driver с единым интерфейсом:
`detect, install, healthcheck, createAccess, importAccess, enableAccess,
disableAccess, revokeAccess, rotateAccess, getTraffic, getLastActivity,
exportConfig`.

- **Xray** — сохраняет старые UUID, создаёт отдельный UUID на каждое устройство,
  формирует vless-ссылку + QR. Не трогает legacy inbound без backup.
- **AmneziaWG** — различает нативный `.conf` и официальный ключ `vpn://`.
  Обычный `.conf` не выдаётся за `vpn://`. Если настоящий `vpn://` невозможно
  сформировать безопасно — честно отдаётся `.conf` с пометкой ограничения.
- **HTTP / SOCKS5** — только для администратора, отдельный login/password на
  каждый доступ.

## Модель совместимости со старыми конфигами

Старые конфиги **продолжают работать**. Система их не пересоздаёт:
аудит обнаруживает их, импорт заносит в БД со статусом `observed`/`imported`,
сопоставление по надёжным идентификаторам (UUID, public key, proxy login,
internal id, server id) переводит в `adopted`/`managed`. Ненадёжно
сопоставленные — `unassigned`, назначаются админом вручную. Управление
(отключение по лимиту и т.п.) применяется только к тем, кем NoVPN реально
умеет управлять.

## Данные и изоляция установок

Dev и production — независимые установки одного кода: раздельные БД, тома,
`ENCRYPTION_KEY`, сессии, Telegram-токены, ключи агентов, SSH-данные,
пользователи, конфиги, статистика и audit log.
