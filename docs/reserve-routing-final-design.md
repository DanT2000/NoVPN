# NoVPN — полный дизайн системы (финал)

Мастер-спека: DNS, резерв, лимиты/устройства, выдача, маршрутизация, диагностика,
каталог, панель. Для владельца — вычитать и утвердить. По каждому пункту коротко
**что / где / как**. Решённое ✅, открытое ❓.

Главный принцип структуры: **ничего не ломать в уже работающем ядре.** Все доработки
ниже — это либо серверная настройка (DNS), либо мягкие надстройки (лимиты, статистика),
либо панель/UI. Ядро маршрутизации (Smart/Full, fake-ip, анти-петля) не переписываем.

## 1. NoVPN DNS — свой резолвер (закрывает целый класс багов)

- **Зачем:** проблема «Сбер/росс. сайты не открываются, лечит перезагрузка» и подобные
  — это зависимость от **чужих резолверов** (Cloudflare 1.1.1.1 / Google 8.8.8.8),
  которые операторы РФ режут, особенно в белых списках. Убираем зависимость.
- **Что:** лёгкий DNS-резолвер на КАЖДОМ нашем VPN-сервере (AdGuardHome/CoreDNS/dnsmasq
  или встроенный DNS движка сервера). Запросы к нему идут **внутри туннеля**, а не
  наружу к 1.1.1.1 → оператор их не видит и не блокирует.
- **Как (клиентский конфиг mihomo), три уровня:**
  1. Российские/прямые домены → **операторский systemDns** (нужен местный IP и прямой
     заход). Остаётся primary — быстро и правильно по гео.
  2. **Fallback и дефолт для всего прочего → NoVPN DNS через прокси** (`nameserver`
     указывает на наш резолвер, а не на Cloudflare). Если операторский DNS в переходном
     окне пуст — падаем НЕ на зарубежный DoH, а на наш DNS через туннель → резолвится.
  3. Проксируемые домены (в VPN) и так резолвятся на стороне сервера (fake-ip + удалённый
     DNS) — уже устойчивы к блокировке.
- **Плюс фикс `systemDns()`** (см. [[sberbank-direct-dns-bug]]): пиновать активную сеть
  по умолчанию + помнить last-good DNS (не обнулять политику в переходном окне). NoVPN
  DNS — вторая линия обороны, `systemDns`-фикс — первая.
- **Стоимость:** минимальна — крошечный резолвер на сервер, ставится тем же скриптом/
  визардом переноса. Бонус: опциональная блокировка рекламы/трекеров, полный контроль.
- **Caveat:** если наш сервер/туннель лёг, NoVPN DNS через него тоже недоступен — но
  тогда мы и так уходим на резерв, а прямые RU-домены держатся на операторском/system DNS.
- **Касается ОБЕИХ платформ:** десктоп имеет ту же слабость — прямые домены из списка
  резолвятся через mihomo `system` (надёжно), но дефолтный `nameserver` = Cloudflare DoH,
  и всё неявное (в т.ч. `MATCH,DIRECT`) уходит на зарубежный DoH ([core.rs](../apps/desktop/src-tauri/src/core.rs)).
- ✅ **Решение (лучшее):** **вариант A — резолвить дефолтный DNS ЧЕРЕЗ туннель**
  (mihomo `proxy-server-nameserver` / маршрутизация DNS через прокси-группу). Плюсы:
  **новый сервер-софт НЕ нужен**, ноль обслуживания, работает и на мобиле, и на десктопе,
  оператор не может заблокировать (это шифрованный трафик к нашему серверу). Прямые
  RU-домены остаются на операторском/`system` DNS (правильный местный IP), а всё прочее
  и фоллбэк — через туннель, а не на 1.1.1.1/8.8.8.8.
- **Опция на потом:** AdGuardHome на серверах — если захотим блок рекламы/трекеров +
  дашборд. Но это ops-нагрузка; для закрытия бага не требуется.

## 2. Граница Happ ↔ наше приложение (ключевое разделение)

- **Happ** = «тупая труба»: одна подписка, **только наши серверы**, без белых списков,
  без резерва, без лимитов. Есть на всех устройствах, «просто работает» — базовый вариант.
- **Наше приложение (NoVPN, Android + Desktop)** = «умное»: белые списки + аварийный
  резерв + **единственное место, где работают лимиты** (оно знает устройство и говорит с
  нашим бэкендом). Всё «умное» собирается и контролируется только здесь.
- **Почему так:** белые списки и аварийные серверы в Happ не отдаём — их логика и учёт
  живут в нашем клиенте. Happ по подписке видит только обычные наши серверы.

## 3. Лимиты — две мягкие «корзины»

- **Две корзины, у каждой свой лимит:**
  1. **Резерв без белых списков** (наш сервер лёг, интернет есть).
  2. **Обход белых списков.**
- **Мягкий лимит** ✅: при исчерпании НЕ рубим всё. Оставляем доступ к нашему серверу
  (чтобы приложение показало статус и красивый экран «Лимит исчерпан»), остальное в этой
  корзине блокируем. Обычный VPN продолжает работать.
- **В панели — просто, пер-юзер:**
  - Базовый: «нажал кнопку → обычные серверы, бесплатно».
  - Оверрайды на юзера: доп. лимит / доступ к белым спискам / приоритет (без лимита).
  - Глобальные дефолты + оверрайд на карточку (без жёсткого перегруза UI).
- **Учёт:** `backup_traffic` уже есть; дельта трафика в режиме корзины (лёгкая переоценка,
  для мягкого лимита хватает).

## 4. Контроль устройств — есть ли смысл

- **Вывод:** смысл в основном для **безлимитных/расшариваемых** подписок (анти-абуз), и
  работает **только в нашем приложении** (Happ устройства не проверить).
- **Рекомендация:** вести продукт **от корзин-лимитов трафика** (ближе к деньгам), а не от
  числа устройств. Число устройств — **опционально и мягко** (видим онлайн, можем
  ограничить), не жёсткий блок.
- **HWID** ✅: чужая (скопированная) подписка → один на всех; наша собственная → по
  устройству. Если провайдер требует, а поле пустое — авто-генерим один, рассылаем.

## 7. Логика клиента (Android + Desktop — единая)

Диагноз: OK / RESTRICTED (белые списки) / SERVER_DOWN / NO_INTERNET. Дерево:
1. Текущий не пропускает → подбор рабочего **обычного** сервера.
2. Обычных нет → диагностика → корзина по типу беды (whitelist/outage), проверка =
   реальный обход (YouTube и др.), российские серверы исключены, **полный туннель**.
3. Перебор по `sort`, возврат на обычный при восстановлении.
4. Пользователь видит только «резервный сервер» + пометку + уведомление про белые списки.

**Статус:** Android — сделано (0.2.x). Desktop — Фаза 1+2 (50 тестов); осталось полный
туннель на резерве + UI.

## 8. Статистика по операторам/регионам (клиент → панель)

- Шлём: оператор (MCC/MNC → имя), тип сети, **грубый регион** (округ, город если выйдет —
  **без GPS/геолокации** ✅), какой сервер сработал/нет.
- Зачем: (а) панель сортирует резерв под оператора → быстрее находится рабочий из сотен;
  (б) видно «на МТС не помогает, на Мегафоне помогла вот эта подписка» → понятно, что
  оплачивать.
- Тумблер «Отправлять статистику», по умолчанию ВКЛ ✅; при первом запуске — короткое
  «продукт как есть; обезличенные данные о качестве связи».

  или тихий ресинк ([[migrate-server-wizard]], [[finland-server-now-france]]).
- **Профиль/меню:** история изменений — не весь список открытым, показывать ~10 +

- **Telegram-выпуск:** проверить, что удобно и рабоче выпускает всё.
- **Дизайн:** общий оставить прежним, точечно упростить для удобства.
- **Прямой трафик и пинг (проверить на тесте):** гипотеза — трафик «напрямую» (игры/
  Steam) не влияет на пинг. Уточнение: в TUN-режиме даже прямой трафик проходит через
  userspace-стек mihomo — оверхед обычно единицы мс (выигрыш в том, что нет крюка через

  netlinkrib ([[sberbank-direct-dns-bug]]) — UDP-игры «напрямую» под VPN на телефоне не
  поедут; на десктопе стек другой. Замерить пинг direct vs VPN-off на Desktop и Android.
