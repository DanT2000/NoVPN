# BUG AUDIT REPORT — NoVPN (сентябрь 2026)

Глубокий аудит всего монорепо на реальные баги, падения, нестабильность и скрытые
edge-cases. Работа велась циклами **ИССЛЕДОВАНИЕ → ПОПЫТКА СЛОМАТЬ → ВОСПРОИЗВЕДЕНИЕ →
ТЕСТ → ИСПРАВЛЕНИЕ → REGRESSION**. Каждая находка верифицировалась по коду перед
исправлением; каждый фикс сопровождается тестом (где харнесс это позволяет) и прогоном
регрессии.

## Методология

- Прогон всех существующих тестов (базовая линия).
- Параллельный статический разбор по областям: HTTP/API панели, слой БД и фоновые
  джобы, ядро VPN (выпуск/подписка/резерв), `packages/shared` + `apps/agent`, Rust-
  клиент десктопа. Плюс ручной разбор фронтендов (web/desktop) и связки расширение↔хост.
- Отдельно проверены сценарии из задания: edge-cases, быстрые повторные действия,
  параллельные действия, race conditions, потеря соединения, ошибки backend/API,
  отсутствующие/битые данные, пустые состояния, большие объёмы, перезагрузка,
  восстановление состояния, несколько процессов/вкладок, истёкшие сессии, ошибки БД,
  утечки ресурсов, зависания, падение всего приложения из-за локальной ошибки.

## Исправленные баги (с тестами и проверкой регрессии)

Серьёзность: **CRIT** — утечка/падение/потеря данных; **HIGH** — обход защиты/долгая
нестабильность; **MED** — ошибочное поведение в edge-case; **LOW** — косметика/мелочь.

### apps/manager (панель)

1. **[HIGH · security] SSRF в резервной подписке.** `PUT /sub/:token/backup/personal`
   фетчил URL от ОБЫЧНОГО пользователя без проверки — можно было заставить панель
   сходить на `169.254.169.254` (метаданные облака), `127.0.0.1:<порт>`, во внутреннюю
   сеть `192.168.x`. → `lib/safeFetch.ts::assertPublicUrl` резолвит хост и отвергает
   внутренние/loopback/link-local/ULA/CGNAT/metadata адреса (fail-closed на мусор).
   Тест `safe-fetch.test.ts`.
2. **[HIGH · crash/DoS] Безлимитное тело ответа → OOM.** Тело резервной подписки
   читалось `res.text()` в обход `Content-Length` (chunked / без заголовка) — многогиг
   ответ клал процесс. → `readTextCapped` читает поток с жёстким лимитом и прерывает.
3. **[HIGH · security] Обход снятия доступа пустым `allowedServers`.** Гварды
   `allowedServers.size > 0` инвертировали пустой список в «все серверы»: сняв у профиля
   ВСЕ серверы, админ оставлял подписку рабочей, а ключи — живыми на серверах. → пустой
   список = «ни одного» (симметрично `issue.ts`/`buildPublicBootstrap`): подписка пуста,
   конфиги идут на отзыв. Тест `allowed-servers-scope.test.ts`.
4. **[HIGH · security] Тихий обход срока действия.** Мусор в `expiresAt` давал
   `new Date(x) < now` == `NaN < num` == `false` → пользователь становился бессрочным.
   Нечисловые лимиты роняли SQLite (500). → `lib/validate.ts` (normCount/normGb/
   normExpiry) → 400 и нормализация ISO. Плюс PATCH: `category`→String, `allowedServers`
   обязан быть массивом (закрыт substring-match по `.includes`). Тест `user-validate.test.ts`.
5. **[MED · рост «навсегда»] `user_history` без прунинга** И грузился ЦЕЛИКОМ на КАЖДОМ
   bootstrap админки (горячий путь, деградация со временем). → прунинг 100/пользователя.
   Тест `log-prune.test.ts`.
6. **[MED · рост «навсегда»] `admin_log` без прунинга** (в отличие от `job_errors`);
   `earliestDataIso` сканировал его целиком. → кап 2000. Тест `log-prune.test.ts`.
7. **[MED · защёлка статуса] Сервер вечно «online» без SSH-кредов.** Потерявший креды
   сервер молча пропускался (`continue`) мимо offline-пути → горел зелёным навсегда. →
   помечаем offline (подтвердить живость нечем).
8. **[MED · зависание] `POST /api/admin/backup/:id/refresh` без try/catch.** Express 4 не
   ловит reject async-обработчика → ответ не отправлялся, запрос висел до таймаута. →
   try/catch → 502.
9. **[LOW] `parseSs` без порта портил host** (`hp.slice(0,-1)` — терялся символ, порт
   NaN). → `splitHostPort` (IPv6 в скобках + отсутствие порта). Тесты в `backup-subparse.test.ts`.
10. **[LOW · DoS-minor] `POST /sub/:token/diag`** гнал тело (до 1 МБ) через map/filter
    до среза в 100. → `slice(0,100)` сразу.

### packages/shared

11. **[MED-HIGH · невалидный конфиг] Ссылка на несоздаваемый балансировщик `lb0`.** При
    умной маршрутизации с ровно одним прокси-каналом и нулём валидных vless правило
    списка ссылалось на `balancerTag:"lb0"`, который в ветке одного канала не создавался
    → Xray отвергал весь профиль. → `lb0` только когда каналов > 1. Тест
    `whitelist-balancer.test.ts` (инвариант «каждый balancerTag существует»); **доказано**:
    на прежнем коде тест падает, на фиксе — зелёный.

### apps/agent (серверный демон)

12. **[HIGH · security] Утечка приватного REALITY-ключа.** При несовпадении формата
    вывода `xray x25519` фоллбэк вшивал ПРИВАТНЫЙ ключ сервера в `pbk=` клиентской ссылки.
    → падаем, а не раскрываем ключ.
13. **[HIGH · учёт трафика] `bytesFrom` терял TiB/PiB** (тера-объёмы → ~единицы байт,
    сильный недосчёт квоты) и брал десятичные множители для двоичных единиц. → двоичные
    степени 1024 + TiB/PiB. Тест `agent-units.test.ts`.
14. **[MED · busy-loop] `config.int` пускал 0/пусто/отрицательное.** `Number('')===0` →
    `setInterval(fn,0)` (флуд control plane), порт 0. → `posInt` требует строго > 0. Тест.
15. **[MED · brick] Повреждённый `identity.json`** бросал → вечный crash-loop без
    пересоздания. → при повреждении личность пересоздаётся; `saveIdentity` пишет атомарно.

### apps/desktop (Tauri-клиент)

16. **[HIGH · гонка] `vpn_disconnect` в обход замка сериализации.** Брал только слот
    движка (`.0`), не замок подключения (`.1`), и мог вклиниться в середину `vpn_connect`
    → человек, нажавший «отключить», оставался подключённым (или прокси указывал мимо
    туннеля). → disconnect берёт `.1` первым (порядок `.1→.0` как у connect).
17. **[MED-HIGH · tight loop] Бесконечный ретрай старта в engine-host.** После неудачного
    `Engine::start` `!alive` снова триггерил старт каждые ~12с (гвард не работал). →
    `failed_epoch` + чистая `needs_restart` (юнит-тесты `enginehost::tests`).
18. **[MED · срыв туннеля] Порванное чтение `control.json`** читалось как `want=false` →
    хост гасил живой туннель. → держим прошлую команду при сбое чтения.
19. **[MED · усечённые файлы] Неатомарные записи `config.yaml`/`control.json`/`host.json`,**
    читаемых другим процессом (mihomo, хост). → `store::atomic_write` (tmp+rename с pid)
    во всех местах.
20. **[test] Красная база десктопа.** `parsing.rs` ждал старое поведение `clean_name`
    (флаг срезан); фикс этой сессии (подтверждён на устройстве — значки 🚀/🏠 видны)
    сохраняет ведущий флаг. Ассерты приведены к верному ожиданию.

### apps/web + apps/desktop (фронтенды)

21. **[HIGH · падение всего SPA] Нет ErrorBoundary.** Исключение при рендере любого
    компонента (на кривых данных API) роняло весь интерфейс в белый экран без
    восстановления (для VPN-клиента — нельзя даже отключиться). → границы последнего
    рубежа в обоих приложениях.
22. **[MED · ложная ошибка] `httpApi`: `JSON.parse` без try/catch** бросал «Unexpected
    token <» на не-JSON ответе шлюза (502/HTML) ещё до обработки статуса — понятная
    «Ошибка 5xx» и мягкий разлогин на 401 не срабатывали. → разбор обёрнут.

## Оставшиеся потенциальные проблемы (не исправлены — задокументированы)

Реальные, но либо ниже приоритетом, либо риск правки выше пользы без отдельной проработки/
подтверждения владельцем. Сгруппировано по серьёзности.

### Стоит запланировать (MED)

- **Реактивация не восстанавливает конфиги.** Снятие `active:false` физически удаляет
  клиента с серверов; включение обратно только ставит `is_active=1` и НЕ перевыпускает —
  «конфиги переживут паузу» не выполняется (совпадает с осознанно отложенным в
  `deferred-hardening`). Нужен re-issue/resync при реактивации.
- **Дайджест помечается «отправленным» до доставки.** `last_digest_day` пишется ДО
  `notifyAdmin` (ошибки проглатываются) — при недоступности Telegram день теряется.
- **`reissue` устройства и standalone-выдача прокси не под `withUserIssueLock`** — узкие
  TOCTOU-окна на границах await (дубли/просроченный конфиг при гонке с `issueForUser`).
- **`revokeAccess` AmneziaWG ломается, если в имени устройства есть `[`** — regex
  `[^[]*` обрывается на скобке в комментарии, peer не вычищается из `.conf` и
  воскресает при рестарте интерфейса (обход отзыва). Нужен структурный разбор блоков.
- **Нет таймаутов** у `shell.run` (execFile) и `controlPlane.fetch` в агенте — зависший
  `docker exec`/hung control plane подвешивает health-эндпоинт и стекует интервалы.
- **`publishBuild` не в транзакции** — краш между записью контента и флагом версии
  оставит рассинхрон «раздаётся новое, версия старая» (краш-only окно).
- **Прочие async-обработчики без try/catch** (`/devices/:id/revoke|delete|cleanup`,
  `/users/:id/active`, `DELETE /users/:id`) — при отказе SSH-операции запрос может
  повиснуть (Express 4). `active` вдобавок пишет `is_active=0` ДО await → частичное
  состояние при сбое.
- **`meta.json` рекламирует per-server subLink для detached-сервера**, который отдаёт 404
  (три пути — meta/aggregate/bootstrap — расходятся по detached).

### Ниже приоритетом (LOW / hardening)

- Рост `app_settings` `low-traffic:*` и осиротевшие `.replaced-<ts>` копии БД.
- `uncaughtException` резюмирует процесс (Node не рекомендует) — лучше graceful-restart.
- Ручная пересборка AutoRoute не под тем же мьютексом, что часовой цикл (дубль работы).
- Аллокация AWG-IP не выходит за один `/24` (>253 пиров на сервере → битый `.conf`).
- `quota_blocked`-устройства показываются в кабинете «активными» с нерабочим конфигом.
- Часовой учёт трафика завышается на сброс счётчика ядра (awg down/up, ребут).
- Desktop: TOCTOU `wait_controller_up` возвращает старый движок при tunnel-реконнекте;
  осиротевший mihomo живёт ≤5с после краха хоста (freshness по времени, не по pid);
  `sub_fetch` без лимита размера тела; `dedupe_names` O(n²) на патологич. дублях именах;
  общий рабочий каталог/pid/log у прокси- и tunnel-движка; распаковка расширения
  преаллоцирует по заявленному размеру из zip-заголовка (zip-bomb).
- Клок-монотонность в троттлах (обратный шаг NTP); границы суток/часа по UTC (03:00 MSK).
- Health-сервер агента слушает все интерфейсы (`server.listen(port)` без host).

### Проверено и НЕ является багом

- Инъекций SQL нет: все значения параметризованы, динамические имена столбцов —
  из схемы, не из запроса. Миграции идемпотентны. Все `setInterval` c `.unref()` и
  гвардом от наложения тиков. `unhandledRejection`-путь защищён от runaway-петли.
  Двух-цикловая гонка записи `routing_files.upstream` уже исключена (AutoRoute-датасеты
  исключены из зеркального цикла). Session fixation закрыт (`regenerate`). Path traversal
  в раздаче файлов приложений закрыт. Cross-user утечки в подписке/резерве нет.

## Что не удалось проверить автоматически

- **Реальный TUN-коннект десктопа** и полный жизненный цикл engine-host с UAC — требует
  Windows-десктоп с правами; гонки connect/disconnect и порванные чтения исправлены по
  рассуждению + юнит-тестам чистой логики, но не под нагрузочным конкурентным прогоном.
- **SSH-цикл sync** (сервер offline при отсутствии кредов) — требует мокинга SSH;
  проверено рассуждением + регрессия repo-тестов.
- **Фактическое сетевое поведение SSRF/OOM** — проверены чистые классификатор и
  cap-чтение; сам fetch на внутренние адреса не выполнялся (и не должен).
- **apps/android** (Kotlin/Compose) — нет тест-харнеса/эмулятора в окружении; в аудит
  кода этой сессии не входил (движок/контракт общие с десктопом).
- **DNS-rebinding** остаточно возможен между проверкой `assertPublicUrl` и `fetch`
  (проверка по имени резолвит все адреса, но TOCTOU остаётся) — для полного закрытия
  нужен pin resolved-IP на само соединение.

## Замечание по доставке

Все правки — на уровне исходников + тестов, закоммичены логическими группами. **Новые
сборки панели/десктопа не публиковались и не деплоились** — это отдельный шаг (сборка
десктопа + загрузка в канал обновлений; деплой панели через Coolify), который стоит
выполнить отдельно, когда решишь выкатывать.
