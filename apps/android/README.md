# NoVPN для Android

Клиент той же модели, что и десктопный: через VPN идёт только то, что нужно,
остальное — напрямую. Подписка, профили и правила маршрутизации разбираются по
тому же контракту — `docs/NOVPN-CLIENT-CONTRACT.md` в корне репозитория.

## Как это устроено

| Слой | Что делает |
|---|---|
| `core/Sub.kt` | разбор подписки (vless/vmess/trojan/ss, Clash-YAML, Xray-JSON панели) |
| `core/Meta.kt` | `meta.json` панели: профили, умный и «Полный VPN», отказы 4xx |
| `core/Lists.kt` | списки AutoRoute (`upstream.json`) и их грамматика |
| `core/Config.kt` | сборка конфига движка mihomo — порт `core.rs` десктопа |
| `vpn/NoVpnService.kt` | системный туннель, запуск движка, сторож, уведомление |
| `vpn/Native.kt` + `cpp/spawn.c` | запуск движка процессом с передачей ему TUN-дескриптора |
| `system/Oem.kt` | разрешения, без которых оболочки закрывают приложение в фоне |

Интерфейс — Jetpack Compose, в той же стилистике, что десктоп: токены цветов
(`ui/Theme.kt`) перенесены из `apps/desktop/src/styles/theme.css`, главный экран
повторяет `Home.tsx` (развилка «Напрямую / Через VPN» с бегущими точками, статус,
тумблер умной маршрутизации, кнопка «Запустить/Отключить» внизу), вкладки те же
четыре: Главная, Маршруты, Подключение, Настройки. Логотип — щит с буквой N на
синем градиенте десктопной иконки; он же в уведомлении и на плитке быстрых
настроек (`system/QuickTile.kt`).

| Слой интерфейса | Что делает |
|---|---|
| `ui/Theme.kt` | токены тёмной и светлой темы, Material-схема из них |
| `ui/Common.kt` | кнопки, карточки, тумблер, сегменты, поля, уведомления, диалог |
| `ui/Icons.kt` | иконки с контурами `icons.tsx` десктопа + логотип |
| `ui/RouteFork.kt` | развилка маршрутов с анимацией точек |
| `ui/Home.kt`, `ui/Screens.kt`, `ui/Routing.kt` | экраны; в «Приложениях» трёхпозиционный выбор Напрямую / Авто / Через VPN и настоящие иконки приложений |
| `ui/Flags.kt` | флаг страны из имени сервера (эмодзи панели или по названию) |
| `ui/AppRoot.kt` | навигация, системная «Назад», онбординг |

Движок — **mihomo** (linux-сборка, см. «Грабли»), тот же, что на десктопе, и конфиг для него собирается из тех
же правил. Туннель поднимает система (`VpnService`), а дескриптор отдаётся движку
через `tun.file-descriptor`: отдельного tun2socks не нужно.

Три вещи на Android сделаны иначе, чем на компьютере, и это не лень:

1. **Правил по процессам нет.** Начиная с Android 10 приложение не может узнать,
   какому процессу принадлежит чужое соединение. Поэтому «приложение напрямую» —
   это исключение из туннеля средствами системы
   (`VpnService.Builder.addDisallowedApplication`), а не правило движка.
2. **`nameserver: system` не работает.** Движок читает `/etc/resolv.conf`, которого
   на Android нет, и молча уезжает на свои зашитые адреса. Системные DNS берутся у
   `ConnectivityManager` и подставляются явно.
3. **Управляющий канал закрыт токеном.** К `127.0.0.1` на телефоне может
   подключиться любое приложение, поэтому `secret` генерируется на каждый запуск.

## Сборка

Нужны Android Studio (SDK 35, NDK 27, CMake) и JDK 17+.

```bash
# 1. Движок (в git его нет, как и mihomo у десктопа)
python scripts/fetch-engine.py

# 2. Путь к SDK
echo "sdk.dir=C:/Users/<вы>/AppData/Local/Android/Sdk" > local.properties

# 3. Сборка и тесты
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
```

APK окажется в `app/build/outputs/apk/debug/`.

Собирается три ABI: `arm64-v8a`, `armeabi-v7a`, `x86_64` (последний — для
эмулятора). Каждый несёт свою копию движка (~50 МБ), поэтому универсальный APK
крупный; для раздачи имеет смысл включить `splits { abi { ... } }`.

## Проверка на устройстве

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb logcat -s novpn.service novpn.engine novpn.boot
adb shell run-as ru.appswire.novpn.debug cat files/engine/engine.log
```

Что проверять обязательно:

- подключение и реальный маршрут (российский сайт — напрямую, заблокированный — через VPN);
- закрыть приложение из недавних: VPN обязан продолжать работать;
- выключить экран на 15–20 минут: связь не должна рваться (если рвётся — ограничения батареи);
- перезагрузка телефона при включённом «Постоянном VPN»;
- смена Wi-Fi ↔ мобильный интернет на ходу;
- отзыв разрешения VPN (запуск другого VPN-клиента) — приложение должно честно показать это.

## Грабли платформы, на которые уже наступили

Это не теория — каждый пункт ломал приложение молча, без единой ошибки на экране.

| Что | Чем кончалось | Как решено |
|---|---|---|
| **android**-сборка mihomo при старте TUN читает `/data/system/packages.xml` (root-only) | слушатель TUN не поднимался, а движок жил и отвечал — «Подключено» при полной тишине в туннеле | берём **linux**-сборки (`mihomo-linux-*`): статические, на Android работают как есть, этой ветки в них нет (`server_notandroid.go`) |
| targetSdk 35 запрещает открытый HTTP **всему** приложению, включая 127.0.0.1 | управляющий канал движка не отвечал, VPN не поднимался вовсе | `network_security_config.xml`: cleartext разрешён только петле |
| `useLegacyPackaging = false` | движок остаётся внутри apk, запускать нечего | флаг включён |
| `nameserver: system` | движок не находит резолвер и молча уезжает на свои зашитые адреса | системные DNS берём у ConnectivityManager с **не-VPN** сети |
| «приложение напрямую» в полном VPN | приложение шло с реального адреса, хотя обещан весь трафик через туннель | исключения применяются только в умном режиме |
| `InetAddress.getByName` для проверки «это адрес?» | «1.2.3» превращался в 1.2.0.3, а домен уходил в блокирующий DNS на пути подключения | свой разбор литерала |
| одна кривая строка в списке панели | движок отвергал **весь** конфиг, VPN переставал работать | маски и IPv6 валидируются, регэкспы проверяются по меркам RE2, а не Java |
| чужой Clash-YAML целиком в конфиг движка | подписка могла открыть на телефоне прокси в локальную сеть | берём только `proxies` и `proxy-groups` |
| две команды подряд (двойное нажатие, sticky-рестарт) | два движка на один порт, потерянный дескриптор туннеля | весь жизненный цикл под одним мьютексом |

## Чего здесь пока нет

- Самообновления APK: Play это запрещает, а для сайта нужен отдельный flavor.
- Расширения для браузера — на Android его нет и не будет.
- Переключения серверов по задержке (ping) — измеряется и показывается у выбранного
  сервера, но выбор по ней не автоматизирован.
