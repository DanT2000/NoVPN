# Как устроен NoVPN Desktop

## Движок — Mihomo, не Xray

Xray не умеет правил по именам процессов. Без них «Discord через VPN» не
сделать в принципе, а это половина смысла продукта. Mihomo умеет и правила по
процессам, и VLESS+REALITY, и TUN — то есть заменяет собой связку из нескольких
движков.

Проверено на живой подписке: правило совпало, процесс определился, соединение
поднялось.

```
[TCP] 127.0.0.1:51933(curl.exe) --> api.github.com:443
      match ProcessName(curl.exe) using NoVPN[Finland 1]
```

Причём **без TUN**, на обычном локальном прокси. Значит правила по приложениям
работают и без прав администратора — TUN понадобится только чтобы захватывать
программы, которые системный прокси игнорируют.

## Порядок правил решает

Mihomo применяет первое совпавшее правило. Первая попытка была с правилами по
приложениям наверху, и проверка сразу показала, чем это кончается: `gosuslugi.ru`,
запрошенный из приложения с правилом «через VPN», уходил за границу и ломался.

Действующий порядок:

```
1. Домены, обязанные идти напрямую   ← сильнее всего
2. Приложения, явно оставленные напрямую
3. Приложения, которым нужен VPN
4. Домены, которым нужен VPN
5. Локальные подсети → напрямую
6. MATCH → напрямую                  ← умолчание
```

Пункт 6 и есть модель продукта: **по умолчанию всё идёт напрямую**, VPN получает
только названное. Поэтому списки перечисляют то, чему нужен VPN, а не наоборот.

Локальные подсети заданы явными `IP-CIDR`, а не `GEOIP,private`: база geoip
тянется из интернета, а приложение обязано подниматься и без него.

## Подписка: любой провайдер, не только NoVPN

Формат распознаётся по содержимому, потому что провайдеры отдают что угодно:

| Что пришло | Как поступаем |
|---|---|
| Clash/Mihomo YAML | берём целиком как основу, подменяем только порты, DNS и правила |
| Xray JSON (формат NoVPN) | вынимаем основной канал каждого профиля |
| Список ссылок | разбираем `vless://`, `vmess://`, `trojan://`, `ss://` |
| То же в base64 | раскодируем и разбираем как список |

Точка подключения хранится **готовой картой параметров для Mihomo**, а не своей
структурой. Сочетаний транспорта и маскировки десятки, и заводить под каждое
поле значит бесконечно догонять чужие релизы.

Запросы к подписке идут под `User-Agent` привычного клиента: часть панелей
отдаёт разный формат в зависимости от него, а некоторые отказывают незнакомым.

## Хранение

`%APPDATA%\NoVPN\`

| Файл | Что там |
|---|---|
| `state.json` | настройки, правила, подписка — всё, что пережило перезапуск |
| `subscription.txt` | сырой текст подписки, чтобы подняться без сети |
| `engine/` | рабочий каталог движка: конфиг и его временные файлы |
| `lists/` | подгруженные с сервера списки |

Запись идёт через временный файл с переименованием: обрыв питания посреди записи
не должен оставлять человека с испорченным конфигом.

**Слоёв правил два, и они раздельны намеренно.** `lists/` приходит с сервера и
при обновлении заменяется целиком; ручные правила лежат отдельно и обновлением
не затрагиваются. При совпадении побеждает ручное, дубликат не создаётся.
Смешать их в одном файле значит рано или поздно затереть чужой труд.

## DNS

Через DoH (`1.1.1.1`, `dns.google`) с режимом `fake-ip`. Обычный DNS провайдера
подменяет ответы для части доменов, и тогда правило «через VPN» приведёт не туда,
куда нужно.

## Что осталось

* TUN — для программ, игнорирующих системный прокси. Нужны права администратора.
* Замер задержки до серверов — сейчас в списке показан протокол вместо `ms`.
* Расширение для браузера и native-messaging хост.
* Установщик NSIS и обновление с GitHub.

## Почему compatible-сборка Mihomo

Обычная сборка Mihomo падает с access violation на эмулированных процессорах —
проверено на Windows Server 2025 с QEMU Virtual CPU. Такие машины у пользователей
будут: виртуалки, старое железо. Compatible-сборка MetaCubeX собрана под базовый
набор инструкций и запускается везде, ценой небольшой потери скорости. Для
приложения, которое расходится по разным конфигурациям, это правильный размен:
лучше чуть медленнее везде, чем падать на части машин.

Проверено на том же сервере: VLESS+REALITY-туннель до Финляндии поднимается,
«напрямую» уходит в РФ, «через VPN» — в Финляндию, IP различаются.
