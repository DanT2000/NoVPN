# Готовые пресеты маршрутизации

Собраны с рабочей машины: реальный список установленного, реальные логотипы,
реальный список российских доменов из действующей подписки.

## Логика обратная привычной

По умолчанию **весь трафик идёт напрямую**. Поэтому перечислять надо не то, что
должно обходить VPN, а наоборот — то, чему VPN нужен. Steam и Lesta в списке
«через VPN» отсутствуют не по забывчивости: им VPN только навредит.

## Файлы

| Файл | Что внутри |
|---|---|
| `apps.json` | 20 приложений: 17 через VPN, 3 явно напрямую |
| `sites.json` | 216 доменов: 70 через VPN, 146 напрямую |
| `icons/` | 11 логотипов 128×128, извлечённых из установленных программ |

Корень — объект с ключом `items`, панель считает по нему количество и разницу
при обновлении.

## Слои правил

Правила живут **двумя раздельными слоями**, и это принципиально:

```
подгруженные списки   ← приходят с сервера, при обновлении заменяются целиком
мои правила           ← добавлены человеком, обновлением не трогаются никогда
```

При совпадении домена или приложения в обоих слоях **побеждает ручное правило**.
Дубликат не создаётся: в списке показывается одна строка с пометкой, что правило
переопределено вручную.

Отсюда следует, что обновление списка не может ни потерять ручное правило, ни
удвоить строку, ни втихую поменять маршрут, выбранный человеком.

## Про приложения, которых нет в списке

`@openai/codex` стоит глобальным npm-пакетом, Claude Code и ChatGPT — расширения
VS Code. Все они работают внутри `node.exe` и `Code.exe`, и правило по имени
процесса для них ненадёжно: под `node.exe` ходит вообще всё, что запускается
через Node.

Поэтому для них работают **правила по доменам** — `openai.com`, `anthropic.com`,
`claude.ai` и остальные из группы «ИИ и разработка». VS Code добавлен и как
приложение: это грубее, зато ловит расширения целиком.
