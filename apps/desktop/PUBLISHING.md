# Публикация обновлений NoVPN Desktop

Приложение проверяет обновления само. Ему нужны две вещи с сервера: **манифест**
(маленький JSON с номером версии) и **сам установщик** (`.exe`). Ниже — точный
контракт: что и по каким адресам отдавать, чтобы «Проверить обновление» в
приложении работало, а сайт мог показывать текущую версию.

## Откуда приложение берёт манифест

По порядку, первый ответивший — рабочий:

1. **Ваша панель** — `https://<домен-из-подписки>/desktop/latest.json`
   Домен берётся из адреса подписки пользователя. Для `vpn.appswire.ru` это
   `https://vpn.appswire.ru/desktop/latest.json`.
2. **GitHub** (запасной) — `https://raw.githubusercontent.com/DanT2000/NoVPN/main/desktop/latest.json`

Панель приоритетнее: `raw.githubusercontent.com` в России часто режется, а это
апдейтер VPN-приложения — обновляться он должен и без уже поднятого VPN.

**Что нужно от вас:** отдавать `latest.json` по пути `/desktop/latest.json` на
том же домене, что и подписка. Если путь другой — скажите, я поменяю одну строку.

## Формат `latest.json`

```json
{
  "product": "NoVPN Desktop",
  "version": "0.1.1",
  "channel": "stable",
  "releasedAt": "2026-08-20",
  "url": "https://vpn.appswire.ru/desktop/NoVPN-0.1.1-setup.exe",
  "sha256": "0e58f3...полные 64 hex-символа...",
  "sizeBytes": 15977919,
  "notes": "Что нового в этой версии — покажется пользователю."
}
```

Приложению **обязательны** ровно четыре поля:

| Поле | Зачем | Правило |
|---|---|---|
| `version` | сравнение с установленной | `МАЖОР.МИНОР.ПАТЧ`, только цифры и точки |
| `url` | откуда качать установщик | прямая ссылка на `.exe`, отдаётся без редиректов на HTML |
| `sha256` | проверка перед запуском | контрольная сумма именно того файла, что лежит по `url` |
| `sizeBytes` | показать размер | размер файла в байтах |

`notes` показывается пользователю. Остальные поля (`product`, `channel`,
`releasedAt`) — для вас и сайта, приложение их не читает.

**Контрольная сумма обязательна и проверяется.** Если `sha256` пустой или не
сходится со скачанным файлом — приложение отменяет установку. Это защита от
подмены установщика: он запускается с правами пользователя. Считать сумму:
`Get-FileHash NoVPN-setup.exe -Algorithm SHA256` (PowerShell) или
`sha256sum` (Linux).

## Как приложение решает, что есть обновление

Сравнение **числовое**, покомпонентно: `version` из манифеста против версии
установленного приложения. `0.10.0` больше `0.9.0` (не по алфавиту). Если
манифестная версия строго больше — показывается «Обновить». Равная или меньше —
«Установлена последняя версия».

Значит: **чтобы выкатить обновление, поднимите `version` в манифесте** и положите
новый `.exe` по адресу из `url`. Пользователи увидят обновление при следующей
проверке.

## Что показывать на сайте как «текущую версию»

То же значение `version` из `latest.json`. Это единый источник правды: и сайт, и
приложение читают одно поле. Не заводите отдельный счётчик версии на сайте —
берите из манифеста, тогда они не разойдутся.

## Что кладём при каждом релизе

1. Собрать установщик (`npm run app:build` в проекте) → получите
   `NoVPN_X.Y.Z_x64-setup.exe`.
2. Положить его на сервер по адресу, который укажете в `url`.
3. Обновить `latest.json`: `version`, `url`, `sha256`, `sizeBytes`, `notes`.

Версия в имени файла и в поле `version` должна совпадать с версией сборки
(`src-tauri/tauri.conf.json` → `version` и `Cargo.toml`). Если хотите, при сборке
могу автоматически проставлять её везде.

## Про минимальную поддерживаемую версию (на будущее)

Если понадобится **принудительное** обновление (старые версии перестают
работать), добавим в манифест `mandatory: true` и `minSupportedVersion`.
Приложение тогда не даст пользоваться, пока не обновится. Пока не реализовано —
скажите, когда понадобится.

## Итог: что нужно от вас

- Отдавать `latest.json` по `/desktop/latest.json` на домене подписки (или назвать
  другой путь — поправлю).
- Отдавать установщик по прямой ссылке из `url`.
- В `latest.json` держать `version`, `url`, `sha256`, `sizeBytes` актуальными.
- На сайте показывать `version` из этого же файла.
